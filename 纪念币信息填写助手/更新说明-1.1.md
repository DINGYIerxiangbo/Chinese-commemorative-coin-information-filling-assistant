# 纪念币信息填写助手 · 1.1.0 整合版说明

> 整合完成时间：2026-11-19。基础为重构版（模块化 banks/filler/2.js/background），并在真实预约页面上逐家实测后补齐了 10 处问题。UI（弹窗、编辑窗、按钮、银行列表、二维码）与原版保持一致，未新增任何功能入口。

## 一、银行清单（12 家）

交通、中国、农业、工商、建设、华夏、邮储、浦发、苏州、徽商、长沙（扫码）、陕西农信（扫码）。

## 二、架构

| 文件 | 作用 |
|---|---|
| `banks.js` | 银行注册表（域名白名单 + 字段选择器 + 数据校验） |
| `filler.js` | 纯 DOM 填写引擎（只填不提交、不点协议、不发短信、不选日期） |
| `2.js` | 内容脚本控制器（自动填写、短信验证码粘贴/WebOTP、页面变化监听） |
| `background.js` | Service Worker，把填写指令路由到正确的 iframe |
| `1.js` / `1.html` | 弹窗（记录列表、导入导出、填入、检查信息） |
| `3.js` / `3.html` | 新增/编辑记录窗口 |

## 五、已知边界（不虚报）

- **兑换日期/时间不自动选**：这版刻意不替用户选日期，避免选错影响兑换；日期、图形验证码、短信发送、协议勾选、最终提交都由用户在银行页面操作。
- 报告里的「已填/确认 N 项」只统计保存资料中确实填入或回读一致的字段，不代表预约表单已满足提交条件。
- 银行侧限制（当期无额度控件禁用、网点 0 额度、需图形验证码后解锁网点、只认可信手势的滚轮控件）会如实提示，不会谎报成功。
- 中行/农行的"区县"在银行侧实际是"有网点的区"或"支行名称"，与保存的行政区别名不一致时会提示手选。

## 六、安装 / 更新

1. 先在弹窗里「导出」备份资料。
2. `chrome://extensions` 打开开发者模式 → 「加载已解压的扩展程序」指向本文件夹（含 manifest.json）。
3. 更新已有解压版：替换文件后点卡片上的 **⟳ 重新加载**，并**把所有已打开的银行页面按 F5 刷新**（内容脚本不会自动重新注入到已打开的标签页）。
4. 打开银行预约表单 → 点记录旁的「填入」→ 按提示核对。

## 七、排查小工具

在银行页面控制台执行下面这行，可让插件把填写结果写到页面属性，便于自查：

```js
document.documentElement.setAttribute('data-dsh-fill-data',
  JSON.stringify({userName:'张三',idCard:'110101199003071006',phone:'13800138000',
                  province:'北京市',city:'北京市',district:'东城区',appointmentQuantity:'2'}));
window.dispatchEvent(new Event('dshCoinFillTest'));
// 然后看：document.documentElement.getAttribute('data-dsh-fill-result')
```
